# DeskLink v1.0.0

DeskLink v1.0.0 是浏览器优先远程桌面技术栈的首个正式打包版本，重点验证了 Windows 被控端、Web 控制端、WebRTC P2P/TURN、低延迟 H.264、无人值守、安全认证、剪贴板与文件传输等核心链路。

## 主要更新

### 浏览器远程控制工作台

- 浏览器控制端支持 H.264 WebRTC 视频与加密 DataChannel。
- 支持全屏、适应窗口、填充、1:1 显示模式、远程截图与 Wake Lock。
- 优先 Direct P2P，失败后自动回退 TURN UDP/TCP/TLS。
- 实时显示线路、RTT、丢包、抖动、解码 FPS 与估算可用带宽。
- 控制端短期 Session Token 仅保存在内存中，并限制到指定目标设备。

### Windows 低延迟 Host

- DXGI Desktop Duplication 屏幕采集。
- D3D11 GPU 缩放与 BGRA → NV12 转换。
- Media Foundation 硬件 H.264 低延迟编码。
- 关闭 B 帧、使用短 GOP 与 CBR 等低延迟配置。
- 对可能输出 AVCC/长度前缀格式的 Media Foundation 编码器进行 Annex-B 统一处理。
- RTP pacing、NACK 重传、PLI/FIR 关键帧恢复。
- 根据网络遥测动态调整码率、FPS 与分辨率，在出现拥塞时优先降低媒体负载，避免长队列不断堆积造成持续高延迟。
- 提供自动、原画、高清、清晰四种画质档位。

### 多显示器与输入

- 会话内枚举和切换同一 DXGI Adapter 下的显示器，无需重启 Agent。
- Windows 虚拟桌面坐标映射，支持负坐标显示器。
- 键盘/鼠标输入注入。
- 断线、窗口失焦或 Service 停止时自动释放可能卡住的按键与鼠标按钮。

### 剪贴板与文件传输

- 双向 UTF-8 文本剪贴板。
- 浏览器不会静默读取或覆盖本地剪贴板，需要用户显式触发。
- 使用独立可靠的 `file-transfer` DataChannel，与信令和普通控制消息分离。
- 浏览器 → Windows 支持拖放与多文件队列。
- Windows → 浏览器支持文件列表和下载。
- 32 KiB 文件分块、SHA-256 完整性校验和 64 位偏移。
- 基于 `bufferedAmount` 的发送背压。
- 支持断线后的恢复/续传行为。
- 未完成上传会保留 `.part` 文件，可继续传输或显式取消清理。
- Windows 默认传输目录：`%USERPROFILE%\Downloads\DeskLink`，可使用 `DESKLINK_TRANSFER_DIR` 修改。

### Windows 无人值守安全

- LocalSystem Windows Service 在活动登录会话中启动并维护 Agent。
- 长期设备凭证与无人值守 Access Code 使用机器范围 DPAPI 存储。
- PID/SID 绑定的本地认证 Broker 将长期设备凭证留在 Service 权限边界内，用户会话 Agent 仅获取短期 Signal Token。
- 每设备独立 `dc2` 凭证，服务端仅保存哈希并支持单设备轮换。
- 控制端 Key 注册表与 target-scoped 短期控制 Session。
- 一次性 HMAC-SHA256 Access Code challenge-response，长期 Access Code 不直接出现在 WebRTC Offer 中。
- 服务端设备吊销会阻止新会话，并周期检查现有信令/P2P 会话。

## 已知限制

这是一个真实可打包的基线版本，但 **v1.0.0 不宣称已经在所有硬件、网络和设备上达到成熟商业远控产品的完整能力**。

- 尚未实现 Windows 登录界面、UAC Secure Desktop 与更高完整性等级的控制；当前 Service 主要覆盖已经登录的活动控制台会话。
- Windows 二进制在 v1.0.0 中尚未进行 Authenticode 签名，SmartScreen 可能弹出警告。
- 尚未实现系统音频/麦克风转发。
- 尚未实现隐私屏/本地显示黑屏。
- 显示器切换目前主要覆盖同一 DXGI Adapter；多 GPU 和多屏同时合成属于后续工作。
- 编码管线支持配置到 3840×2160，但 4K/HDR/4:4:4/高刷新率尚未完成覆盖 Intel/NVIDIA/AMD 和代表性浏览器的真实硬件验证，因此当前版本不作保证。
- Safari 与移动浏览器仍需要更广泛的设备测试矩阵；v1.0.0 主要验证 Chrome / Edge 控制端。
- Web 网络地址在 v1.0.0 中仍以 Vite 构建期配置为主；后续版本会增加运行时配置能力。
- 生产部署仍需要自行准备 HTTPS/WSS 反向代理、账号/控制端凭证、合理区域的 TURN Relay 和监控体系。

## 安全与部署建议

无人值守 Host 请使用：

```powershell
desklink-service.exe --store-device-credential
desklink-service.exe --store-access-code
```

将长期凭证写入 DPAPI，不要把这些秘密长期放在机器环境变量中。公网环境必须使用 WSS/HTTPS 与运行时 TURN 临时凭证。

详细说明请参阅：

- `docs/WINDOWS_SERVICE.md`
- `docs/DEVICE_AUTH.md`
- `docs/PRODUCTION_NETWORK.md`
- `packages/protocol/PROTOCOL.md`
