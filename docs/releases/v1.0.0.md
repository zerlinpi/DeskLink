# DeskLink v1.0.0

DeskLink v1.0.0 is the first packaged release of the browser-first remote desktop stack.

## Highlights

### Browser remote-control workbench

- Browser controller with H.264 WebRTC video and encrypted DataChannels.
- Immersive remote workbench with fullscreen, fit/fill/1:1 display modes, snapshot capture and Wake Lock.
- Direct P2P preferred with TURN UDP/TCP/TLS fallback.
- Live route, RTT, loss, jitter, decode FPS and available-bitrate diagnostics.
- Runtime controller sessions: short-lived, target-scoped controller tokens stay in memory and are not stored in localStorage/sessionStorage.

### Low-latency Windows host

- DXGI Desktop Duplication capture.
- D3D11 GPU scaling and BGRA -> NV12 conversion.
- Media Foundation hardware H.264 with low-latency configuration, no B-frames and short GOPs.
- Annex-B normalization for Media Foundation encoders that emit AVCC/length-prefixed access units.
- RTP pacing, NACK retransmission and PLI/FIR keyframe recovery.
- Telemetry-driven bitrate/FPS/resolution adaptation that degrades quality before allowing long media queues to accumulate.
- User quality profiles: Auto, Original, High and Clear.

### Multi-monitor and input

- In-session monitor enumeration and same-DXGI-adapter monitor switching without restarting the Agent.
- Virtual-desktop coordinate mapping, including negative monitor origins.
- Keyboard/mouse injection with stuck-input release on disconnect, blur and Service shutdown.

### Clipboard and file transfer

- Explicit bidirectional UTF-8 text clipboard bridge; the browser never silently reads or overwrites the local clipboard.
- Dedicated reliable `file-transfer` DataChannel, separate from signaling and control messages.
- Browser -> Windows drag/drop and multi-file queue.
- Windows -> browser file listing and download from the dedicated DeskLink transfer directory.
- 32 KiB chunks with SHA-256 verification and 64-bit offsets.
- `bufferedAmount` backpressure and reconnect/resume behavior.
- Upload partial files are retained for resume and cancelled uploads can explicitly remove their `.part` file.
- Default Windows transfer directory: `%USERPROFILE%\Downloads\DeskLink` (override with `DESKLINK_TRANSFER_DIR`).

### Unattended Windows security

- LocalSystem supervisor Service launches the Agent in the active logged-in user session.
- Machine-scope DPAPI storage for the durable device credential and unattended Access Code.
- PID/SID-bound local authentication broker keeps the long-lived device credential inside the Service and gives the user-session Agent only short-lived Signal Tokens.
- Independent per-device `dc2` credentials with server-side hash registry and per-device rotation.
- Target-scoped controller key registry and short-lived controller sessions.
- One-time HMAC-SHA256 Access Code challenge-response; the reusable Access Code is not carried in WebRTC offers.
- Server-driven `device-revoked` termination plus periodic revocation sweep for active signaling/P2P sessions.

## Release assets

- `desklink-windows-v1.0.0-x64.zip` — Windows Agent, Service and PowerShell install/uninstall helpers.
- `desklink-web-v1.0.0.tar.gz` — static browser-controller build output.

- `SHA256SUMS.txt` — checksums for release artifacts.

## Known limitations

This release is a real packaged baseline, but it does **not** claim complete feature parity with mature commercial remote-control products on every device/network.

- Windows logon screen, UAC Secure Desktop and higher-integrity control are not implemented. The Service covers the active logged-in console session.
- Windows binaries are not Authenticode-signed in v1.0.0; SmartScreen may warn.
- Audio/microphone forwarding is not implemented yet.
- Privacy screen / local-display blackout is not implemented yet.
- Monitor switching currently covers outputs on the same DXGI adapter; multi-GPU and simultaneous all-monitor compositing are future work.
- The encoder pipeline supports configuration up to 3840x2160, but 4K/HDR/4:4:4/high-refresh behavior has not been validated across representative Intel/NVIDIA/AMD hardware and browsers and is not advertised as guaranteed in this release.
- Safari/mobile-browser behavior requires a broader device test matrix; Chrome/Edge remain the primary controller targets for v1.0.0.
- Production deployment still requires your own HTTPS/WSS reverse proxy, account/controller provisioning and geographically appropriate TURN infrastructure.

## Security/deployment guidance

For unattended hosts, store the `dc2` device credential and Access Code through `desklink-service.exe --store-device-credential` and `--store-access-code`; do not place those secrets in machine environment variables. Use WSS/HTTPS and runtime TURN credentials for internet deployment.

See `docs/WINDOWS_SERVICE.md`, `docs/DEVICE_AUTH.md`, `docs/PRODUCTION_NETWORK.md` and `packages/protocol/PROTOCOL.md` for deployment and protocol details.
