# DeskLink v1.0.4

DeskLink v1.0.4 继续围绕“不是 Demo，而是能长期作为被控端使用”推进。这一版重点解决高刷新率真正接线、RDP/Session Agent 选择、Windows 锁屏/桌面切换后的黑屏恢复，以及网络瞬断后 Ctrl/Alt/鼠标按钮可能残留的问题。

## Windows：15–144 FPS 高刷新率真正接入主链路

此前高刷新相关策略存在，但实际 Agent 仍有 60 FPS 上限和固定等待/发送节奏。本版本已经把高刷能力接入真实视频路径：

- `DESKLINK_FPS` 支持 15–144；
- `DeskLink.exe` 设置界面可以直接配置目标 FPS；
- `install-service.ps1` 支持 `-Fps` 与可选 `-BitrateBps`；
- 自适应帧率使用稳定档位：

```text
144 -> 120 -> 90 -> 60 -> 45 -> 30 -> 24 -> 15
```

- DXGI 抓屏等待时间会随目标 FPS 缩短，避免固定 16 ms 等待成为高刷隐藏上限；
- 默认媒体码率随高刷新目标提高；
- RTP pacing 带宽/发送间隔同步为高刷新流留出余量。

### 高刷硬件兼容降级

144 FPS 是目标能力，不是对所有电脑/网络的保证。

如果 D3D11 GPU 转换或 Media Foundation 硬件 H.264 Encoder 无法按请求的高 FPS 初始化，Agent 会尝试更低的兼容高刷档位，而不是直接让视频失效。

实际可用帧率仍取决于显示器刷新率、GPU/驱动、硬件编码器、网络容量以及浏览器解码/显示能力。

## Windows：RDP / Windows Server 活跃会话选择

Service 过去主要依赖 `WTSGetActiveConsoleSessionId()`，这对物理桌面有效，但在 RDP-only / Windows Server 场景可能没有合适的 Console 用户会话。

v1.0.4 增加独立的 active-session 选择模块：

1. 可用时优先真实活动 Console 用户；
2. 否则枚举 Terminal Services Session；
3. 选择存在真实用户且为 `WTSActive` 的交互会话；
4. Session 切换后清理旧 Agent 并在新会话中重新启动。

这让 Service/Session Agent 模型更接近真正的无人值守主机，而不是只适用于当前物理桌面。

## Windows：锁屏/用户切换后 DXGI 自动恢复

修复一个会导致“鼠标键盘还能控制，但画面永久黑屏”的问题。

DXGI Desktop Duplication 在以下场景可能返回 `DXGI_ERROR_ACCESS_LOST`：

- Windows 锁屏/解锁；
- Fast User Switching；
- Session/Desktop 切换；
- 显示模式变化；
- 部分 UAC/桌面切换过程。

旧逻辑在立即重建失败后可能留下空的 Duplication 对象，而后续 `Acquire()` 不再尝试恢复。

现在 DeskLink 会：

- 保留 D3D11 Device/Adapter；
- 在 Duplication 不可用时继续尝试重建；
- 使用有上限的退避避免持续占用 CPU/刷日志；
- 回到正常可访问桌面后自动恢复画面，不要求用户重启 Service/Agent。

**注意：这并不代表已经支持 Windows 登录界面或 UAC Secure Desktop 控制。** 当前版本不会通过关闭 UAC、修改安全策略等方式伪造该能力。

## Windows：网络瞬断后的输入释放更可靠

远控最危险的体验问题之一不是“少一帧”，而是 Ctrl/Alt/Shift/Win 或鼠标按钮在断线时留在被控电脑上。

本版本把输入释放从“主要依赖浏览器/DataChannel close”提升为 Host 侧 authority-loss fail-safe：

- PeerConnection `Disconnected` / `Failed` / `Closed` 会释放已注入输入；
- `control` 或 `pointer` DataChannel 关闭会释放输入；
- 浏览器 blur/hidden/disconnect 仍主动发送 `release-all`；
- Service/Agent shutdown、Session replacement、设备吊销仍执行清理。

### 修复输入状态记账竞态

同时修复了 `SendInput` 与 pressed-state 记账之间的竞态：

- Key/Button 注入和状态登记现在串行化；
- 高频 Pointer Move 不进入该锁，不影响鼠标移动热路径；
- `ReleaseAllInjectedInput()` 只有在实际 `KEYUP` / `MOUSEUP` 成功后才删除跟踪状态；
- 如果因为临时 UIPI/桌面权限边界导致释放失败，状态会保留，后续 cleanup 可以再次尝试。

## Windows CI / Release：新增长期回归保护

此前新增的高刷策略和活跃 Session smoke 只在一次性验证流程中运行。本版本把它们加入正式 CI 和正式 Release 构建：

- H.264 Annex-B smoke；
- High-refresh video policy smoke；
- Active Windows/RDP session selection smoke；
- Access Code proof vector；
- DPAPI protected-secret smoke；
- Service authentication broker smoke；
- Windows portable dependency validation。

一次性源码补丁 workflow 已在验证完成后删除，不作为长期仓库机制保留。

## 当前仍未完成的产品能力

本版本没有把尚未实现的功能标成“已完成”。当前主要缺口仍包括：

- Windows 系统声音 / 麦克风 WebRTC 音频；
- 无公网 Signal Server 的 LAN Direct 自动发现和连接；
- Windows 登录界面 / UAC Secure Desktop / Ctrl+Alt+Del 的最小特权 Broker；
- 显式 NVENC / Intel oneVPL / AMD AMF 后端选择（当前仍以 Media Foundation 硬件 MFT 为主）；
- 虚拟显示器、隐私屏、虚拟 HID / Gamepad；
- 安全自动更新与失败回滚；
- Windows 10/11 + Intel/NVIDIA/AMD + 1h/8h/24h/72h 的完整实机稳定性矩阵。

## 关于 Windows SmartScreen / 签名

仓库具备可选 Authenticode 发布签名流程，但只有配置了受信任代码签名证书 Secret 时才会真正签名。

没有配置 `WINDOWS_SIGNING_CERT_BASE64` / `WINDOWS_SIGNING_CERT_PASSWORD` 时，Release 仍会生成测试/开发包，但 Windows 可能继续显示“未知发布者 / Windows 已保护你的电脑”。代码本身无法合法伪造受信任发布者。

## 升级建议

Windows 用户建议升级完整 ZIP，而不是只替换单个 EXE：

1. 下载 `desklink-windows-v1.0.4-x64.zip`；
2. 完整解压；
3. 以管理员身份运行 `DeskLink.exe`；
4. 检查原配置和目标 FPS；
5. 点击“安装 / 更新并启动”；
6. 再执行“连接诊断”。

公网部署仍需要可访问的 DeskLink Signal 服务；复杂 NAT/CGNAT 场景仍建议配置 TURN。
