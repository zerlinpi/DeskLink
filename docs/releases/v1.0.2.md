# DeskLink v1.0.2

DeskLink v1.0.2 继续聚焦“下载后能配置、出问题能定位、服务器更容易部署”，并修复 v1.0.1 中文 UI 后暴露出的交互回归。

## Windows：`DeskLink.exe` 新增一键连接诊断

Windows 图形化管理器现在不仅负责安装，还可以直接检查远控链路：

- DeskLink Windows Service 是否正在运行；
- 设备 ID 格式；
- 无人值守访问码是否已使用 machine-scope DPAPI 保存；
- Signal `/healthz` 是否能从被控端访问；
- 公网 Signal 是否错误使用 `ws://`；
- STUN 是否配置；
- TURN 主机 DNS 与 TCP 端口是否可达；
- Signal Token 模式是否已配置受保护的 `dc2` 设备凭证；
- 是否已配置短期 TURN Credential API。

诊断结果分为：

- `[通过]`：当前基础检查正常；
- `[警告]`：不一定阻断，但公网/复杂 NAT/生产环境存在风险；
- `[失败]`：会直接阻断当前远控链路，应优先处理。

新增：

- **复制设备 ID**；
- **复制诊断**；
- 安装/更新完成后自动运行一次诊断；
- 诊断报告不会包含访问码或 `dc2` 明文。

该版本的 Windows 管理器已经在 GitHub Windows runner 上通过：

- CMake / MSVC Release 编译；
- portable dependency 检查；
- H.264 Annex-B smoke；
- Access Code proof vector；
- DPAPI protected secrets；
- Service auth broker。

## Web：连接失败不再只有一句“连接异常”

Web 控制端增加可操作的中文故障提示，例如：

- 访问码错误 → 提示检查远端 `DeskLink.exe` 的访问码；
- 远端未配置访问码 → 提示在 Windows Host 设置无人值守访问码；
- 设备被撤销 → 提示重新生成/配置设备凭证；
- 控制端授权被拒绝 → 提示检查账号、密钥和 `AllowedDevices`；
- TURN 凭证失败 → 提示检查 Credential API、HTTPS 和共享密钥；
- Signal 错误 → 提示检查 WSS、WebSocket 反代升级和防火墙；
- 远端离线 → 提示检查 Windows Service 与 Signal 可达性；
- 控制端/被控端协议不兼容 → 提示统一版本。

## Web：修复中文化后的功能回归

此前浏览器兼容性检查和“最近设备”部分逻辑仍依赖英文 `Connect`/placeholder 文案。中文 UI 改造后，这种做法容易失效。

v1.0.2 改为使用稳定的：

- `data-connection-action="connect|disconnect"`；
- `data-role="target-device"`。

因此：

- 不支持 WebRTC/H.264/Web Crypto 的浏览器仍会正确阻止连接；
- 最近设备记录/回填不再依赖按钮显示语言；
- 后续继续修改 UI 文案不会破坏控制逻辑。

## 生产服务器：新增 Bootstrap + HTTPS/WSS 一体部署

新增 `infra/production/`：

- `bootstrap.sh`；
- `docker-compose.yml`；
- `.env.example`；
- `Caddyfile`；
- 部署说明。

Bootstrap 会生成：

- 独立随机 Signal Auth Secret；
- 独立随机 TURN REST Secret；
- `dc2` Windows 设备凭证；
- `ck1` Web 控制端密钥；
- 只保存凭证 SHA-256 哈希的设备 registry / controller registry。

生产 Compose 提供：

- Caddy 自动 HTTPS；
- Web Nginx 静态站点；
- `/ws` 同源 WebSocket 代理；
- `/api/v1/*` 同源 Signal API 代理；
- Signal 容器；
- coturn REST 临时凭证模式；
- Direct P2P 优先、TURN fallback。

服务器部署路径从手动拼接服务进一步收敛为：

```bash
cd infra/production
./bootstrap.sh control.example.com 203.0.113.10 office-pc-01 admin
docker compose up -d --build
```

## Windows SmartScreen

v1.0.2 继续保留 Authenticode 自动签名流程，但**只有仓库配置了受 Windows 信任的 OV/EV 代码签名证书时，发布物才会真正签名**。

如果签名 Secret 未配置，Release 会明确输出 warning 并继续生成 unsigned 测试包。此时 Windows 仍可能显示“未知发布者 / Windows 已保护你的电脑”。这不能通过修改程序代码伪造解决。
